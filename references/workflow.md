# 工作流程與狀態

## 角色

業務負責客戶與商務資訊；工程確認料號、圖面、材質與可製造性；採購確認外購成本；生管確認可承諾量與交期；財務確認稅務處理、授信及付款；主管核准折扣與例外。角色可兼任，但任何分權需求由公司政策定義。

## 七個能力的輸入／輸出

| 能力 | 輸入 | 輸出 | 失敗或缺資料 |
|---|---|---|---|
| 收件 intake | 郵件 ID、來源內容雜湊、客戶與租戶 | 不變事件、案件代碼 | 格式錯誤拒收；同事件改擷取值標記衝突 |
| 擷取 extract | Email/PDF/Excel、OCR | 帶來源定位的 case.json | 密碼／損壞文件記錄待補，不跳過品項 |
| 驗證 validate | case.json、技術規格 | 缺漏／衝突、補件草稿 | 關鍵欄位缺漏阻擋，其他品項可繼續準備 |
| 匹配 match | 客戶料號、產品主檔 | 精確候選、版本／單位差異 | 歧義交人工；新料交工程 |
| 計價 calculate | 核定政策、有效成本、數量與條件 | 數字可重算的報價與 blockers | 不支援情境拒算，不默默忽略 |
| 審核 review | 完整報價雜湊、真實審核事件 | 角色核准與期限 | 核准失效重新審；不可自造核准 |
| 核單 reconcile | 報價、PO、當日 | 條件與品項差異 | 有差異先協調；欄位一致仍需授權 |

## 案件狀態機（由宿主持久化）

RECEIVED → EXTRACTED → NEEDS_INFO 或 MATCH_REVIEW → COST_PENDING → DRAFT → REVIEW_PENDING → APPROVED → SENT → PO_RECEIVED → PO_REVIEW → ORDER_PENDING → ORDER_CREATED → CLOSED。

- NEEDS_INFO 收到補件可回 EXTRACTED，原文與歷次版本不覆寫。
- APPROVED 後任何內容、依據、政策或收件人變更：新 revision，回 DRAFT，失效所有舊核准。
- 報價過期：EXPIRED；客戶取消：CANCELLED；失單：LOST。終止自動跟進。
- 外部寫入無法確定結果：ACTION_UNKNOWN；查詢外部記錄，確認後轉 SENT／ORDER_CREATED 或回待執行，不可直接當失敗重做。
- 單一步驟失敗：ERROR，保留 checkpoint、錯誤碼、重試次數與負責人。恢復從已驗證 checkpoint 開始。

## 一次案件的交付格式

1. 案件／客戶／負責人／狀態。
2. 品項、數量、單位、版本與來源。
3. 缺漏、矛盾、待確認負責人及影響。
4. 料號候選及人工技術確認。
5. 內部價格、費用、毛利、有效性與依據。
6. 客戶格式草稿（不得含內部資訊）。
7. 必要核准與指定報價雜湊。
8. 寄送／建單動作與服務端回執；未執行寫「未執行」。

## 跟進規則

預設只產生第 3、7 工作天提醒建議，由公司設定啟用。Asia/Taipei 時區；工作日須讀公司行事曆，不能只排除週末。客戶有回應、拒絕、退訂、案件過期或取消即取消待發提醒。每個追蹤事件獨立 action key，不重複發送。正式啟用郵件自動跟進需要使用者既有授權及可信收件人。

## 自我改善

記錄更正欄位、原因、人工耗時、失單原因；定期彙總常見問題並建議修改主檔或規則。不得將單一客戶附件寫入全域提示、不得自動改毛利門檻、不得跨客戶重用機密。所有規則更新有版本、回放測試與指定人核定。
